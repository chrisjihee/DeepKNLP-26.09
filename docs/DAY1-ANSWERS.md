### 미션

### `m-tc-1` — 분류 head의 출력을 몇 개로 둘까

**문제.**

주제분류는 뉴스 제목을 **7가지 주제 중 하나**로 나눕니다
(`TC_LABELS = ['IT과학','경제','사회','생활문화','세계','스포츠','정치']`).

사전학습된 인코더 위에 얹는 분류 head는 **라벨마다 점수 하나**를 냅니다.
`num_labels` 에 무엇을 넣어야 할까요?

```python
return AutoModelForSequenceClassification.from_pretrained(MODEL, num_labels=____)
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `len(train_rows)` | 학습 예제 개수(800)입니다. 출력 개수는 데이터가 몇 건인지와 아무 상관이 없습니다. |
| 2 | `len(TC_LABELS)` | **정답** |
| 3 | `1` | 출력이 하나면 점수를 하나만 냅니다. 그것은 값을 맞히는 회귀에 쓰는 형태이고, 7개 중 하나를 고를 수는 없습니다. |
| 4 | `MAX_LEN` | 토큰 길이 상한(128)입니다. 문장을 몇 토큰까지 볼지를 정하는 값이라 라벨과 무관합니다. |

**해설.**

**`len(TC_LABELS)`** — 즉 7입니다.

분류 head는 `hidden_size → num_labels` 선형층이라 **출력 개수가 곧 라벨 개수**입니다.
7보다 작게 주면 모델은 만들어지지만, 라벨 5·6이 들어오는 순간 손실 계산에서 인덱스 범위를 벗어나 오류가 납니다(GPU에서는 `device-side assert`).

`7` 이라고 직접 적어도 지금은 돌아가지만, **라벨 목록의 길이로 쓰는 편이 안전합니다** — 라벨이 늘거나 줄어도 코드를 안 고쳐도 됩니다.

```python
return AutoModelForSequenceClassification.from_pretrained(MODEL, num_labels=len(TC_LABELS))
```

**참고 자료.** [transformers — 문장 분류 태스크 안내](https://huggingface.co/docs/transformers/tasks/sequence_classification) · [AutoModel 계열 문서](https://huggingface.co/docs/transformers/model_doc/auto) · [KLUE 벤치마크 (YNAT 라벨 정의)](https://klue-benchmark.com)

### `m-tc-2` — 정답 라벨을 어떤 형태로 넣을까

**문제.**

모델은 라벨을 **0부터 시작하는 정수**로 받습니다. 원본 데이터에는 이미 그 정수가 들어 있습니다.

예제 하나를 열어 보면 이렇게 생겼습니다.

```python
r["input"]["text"]    # '유튜브 내달 2일까지 크리에이터 지원 공간 운영'
r["gold"]             # 'IT과학'      ← 사람이 읽는 라벨
r["raw"]["label"]     # 0            ← TC_LABELS 순서의 정수
```

빈칸에 무엇을 넣어야 할까요?

```python
enc["labels"] = [____ for r in rows]
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `int(r["raw"]["label"])` | **정답** |
| 2 | `r["gold"]` | `'IT과학'` 같은 **문자열**이 들어갑니다. 모델은 라벨을 정수로 받으므로 손실 계산에서 형이 맞지 않아 오류가 납니다. |
| 3 | `TC_LABELS[r["gold"]]` | 순서가 뒤집혔습니다. `TC_LABELS` 는 정수로 찾는 목록이고 `r["gold"]` 는 문자열이라, 문자열로 목록을 찾으려다 오류가 납니다. |
| 4 | `float(r["raw"]["label"])` | 값은 맞지만 **실수**가 됩니다. 분류 손실(교차엔트로피)은 정수 라벨을 받으므로 형이 맞지 않습니다. 실수 라벨은 회귀에 씁니다. |

**해설.**

**`int(r["raw"]["label"])`**

`r["gold"]` 는 사람이 읽는 문자열(`'IT과학'`)이고, 모델에게 줄 것은 **정수 인덱스**입니다.
원본 데이터의 `raw.label` 이 이미 `TC_LABELS` 순서의 0~6 정수이므로 그대로 쓰면 됩니다.
`int(...)` 로 감싸는 것은 JSON에서 읽은 값의 형을 확실히 하기 위한 습관입니다.

```python
enc["labels"] = [int(r["raw"]["label"]) for r in rows]
```

**완성된 셀 전체입니다.** 앞 문항까지 다 풀었으니 여기서는 빈칸 없이 보여 줍니다 — 아래 [복사]를 눌러 미션 셀에 그대로 붙여 넣으셔도 됩니다.

```python
def build_model():
    # 사전학습된 인코더 위에 '라벨 수만큼 출력이 있는 선형층'(분류 head)을 새로 얹는다.
    # 이 층은 무작위로 시작하므로 "일부 가중치가 초기화되지 않았다"는 경고가 나오는 것이 정상이다.
    return AutoModelForSequenceClassification.from_pretrained(MODEL, num_labels=len(TC_LABELS))


def encode_choice(tokenizer, rows, max_len=MAX_LEN):
    enc = tokenizer([r["input"]["text"] for r in rows], truncation=True, max_length=max_len)
    enc["labels"] = [int(r["raw"]["label"]) for r in rows]
    return Dataset.from_dict(dict(enc))
```

### `m-tc-3` — 라벨 번호를 무엇으로 되돌릴까

**문제.**

이 실습의 목적은 **BERT · T5 · LLM 셋을 같은 자로 재는 것**입니다.
그러려면 셋의 출력 형식이 같아야 합니다.

- LLM·T5 는 처음부터 `경제` 같은 **라벨 이름을 글자로** 써냅니다.
- BERT 는 라벨마다 점수를 냅니다. 가장 높은 자리를 고르면 **번호**(0~6)가 나옵니다.

그 번호를 이름으로 되돌려야 같은 채점 함수에 넣을 수 있습니다.

```python
best = logits.argmax(-1)          # 라벨 번호 (0~6)
return [____[int(i)] for i in best]
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `TC_LABELS` | **정답** |
| 2 | `train_rows` | 학습 예제 목록입니다. 번호로 찾아 들어가면 예제가 나오지 뒤 라벨 이름이 나오지 않습니다. |
| 3 | `logits` | 모델이 낸 점수 자체입니다. 이미 여기서 번호를 뽑아냈으므로 다시 넣을 것이 없습니다. |
| 4 | `eval_rows` | 평가 예제 목록입니다. 여기 든 것은 문제와 정답이지 라벨 이름 목록이 아닙니다. |

**해설.**

**`TC_LABELS`** 입니다.

`TC_LABELS` 는 `['IT과학','경제','사회','생활문화','세계','스포츠','정치']` 이고, **이 순서가 곧 라벨 번호**입니다.
0번이 `IT과학`, 6번이 `정치` 입니다. 그래서 번호로 이 목록을 찾아 들어가면 이름이 나옵니다.

**왜 굳이 문자열로 되돌리는가.** 이 과정의 목표는 BERT·T5·LLM 을 나란히 비교하는 것입니다.
T5 와 LLM 은 애초에 `경제` 라고 **글자로** 답합니다. BERT 만 숫자를 냅니다.
여기서 형식을 맞춰 두면 셋을 **하나의 채점 함수**(`common.score_task`)에 그대로 넣을 수 있습니다.
형식이 다르면 채점을 세 벌 만들어야 하고, 그러면 비교가 공정한지 아무도 확신할 수 없게 됩니다.

**순서가 곧 약속입니다.** 이 목록의 순서는 원본 데이터의 정수 라벨 0~6 과 맞춰 둔 것입니다.
목록 순서를 바꾸면 모델은 그대로인데 채점만 틀리기 시작합니다 — 오류도 나지 않아서 알아채기 어렵습니다.

```python
return [TC_LABELS[int(i)] for i in best]
```

**참고 자료.** [transformers — 문장 분류 (id2label / label2id)](https://huggingface.co/docs/transformers/tasks/sequence_classification) · [NumPy argmax](https://numpy.org/doc/stable/reference/generated/numpy.argmax.html)

### 퀴즈

### `q-tc` — num_labels 를 5로 주면 어떻게 될까

**문제.**

주제분류의 라벨은 7가지입니다. 그런데 실수로 이렇게 썼다고 해 봅시다.

```python
model = AutoModelForSequenceClassification.from_pretrained(MODEL, num_labels=5)
```

무슨 일이 벌어질까요?

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `모델을 만들 때 바로 오류가 난다` | 만드는 단계에서는 라벨 개수만 보고 head 를 얹을 뿐, 데이터를 보지 않습니다. 그래서 오류가 나지 않습니다. |
| 2 | `모델은 만들어지고, 라벨 5·6 이 든 배치에서 손실을 계산할 때 오류가 난다` | **정답** |
| 3 | `아무 오류 없이 학습되고, 라벨 5·6 은 자동으로 4 로 합쳐진다` | 그런 자동 병합은 없습니다. 범위를 벗어난 라벨은 조용히 고쳐지지 않고 오류로 드러납니다. |
| 4 | `학습은 되지만 정확도가 정확히 5/7 로 고정된다` | 그런 규칙은 없습니다. 애초에 학습이 손실 계산에서 멈춥니다. |

**해설.**

**모델은 만들어지고, 손실을 계산할 때 터집니다.**

`from_pretrained` 는 라벨 개수만큼 출력층을 얹을 뿐 데이터를 보지 않습니다. 문제가 드러나는 곳은
라벨 5나 6이 든 배치에서 교차엔트로피를 계산하는 순간입니다 — 타깃은 `0..num_labels-1` 범위여야 하는데
범위를 벗어났기 때문입니다.

**오류가 보이는 모습이 장치에 따라 다릅니다.** CPU 에서는 `IndexError` 계열로 어디가 문제인지 비교적 친절하게
나오지만, GPU 에서는 `CUDA error: device-side assert triggered` 로 뜨고 **엉뚱한 줄을 가리키는 것처럼**
보입니다. 커널이 비동기로 돌기 때문입니다. 이런 메시지를 만나면 라벨 범위를 먼저 의심하세요.

그래서 코드에 `7` 을 직접 적지 않고 **`len(TC_LABELS)`** 로 쓰는 것이 습관으로 좋습니다.

**참고 자료.** [PyTorch CrossEntropyLoss — 타깃은 0..C-1 범위의 인덱스](https://pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html) · [transformers — 문장 분류](https://huggingface.co/docs/transformers/tasks/sequence_classification)

### `q-tc-2` — 왜 주제분류에만 macro-F1 인가

**문제.**

§6 의 `L.evaluate` 는 `common.score_task` 로 채점합니다. 그 함수는 라벨을 고르는 태스크 셋(감성분류 `cls` · 자연어추론 `nli` · 주제분류 `tc`)을 **같은 자리에서** 채점하는데, 주제분류에만 지표를 하나 더 붙입니다.

```python
out = {"accuracy": ..., "broken_format": ...}
if task == "tc":
    out["macro_f1"] = ...        # 주제분류에만 붙는다
```

세 태스크 평가셋의 정답 분포는 이렇습니다.

```
감성분류   500건 · 긍정 230 · 부정 270
자연어추론 300건 · 함의 99 · 모순 104 · 중립 97
주제분류   300건 · 사회 127 · 경제 48 · 생활문화 39 · 정치 29 · 세계 23 · IT과학 19 · 스포츠 15
```

왜 주제분류에서만 정확도 옆에 이 지표를 함께 볼까요?

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `감성분류·자연어추론은 정확도가 이미 충분히 높아서, macro-F1 을 더 봐도 새로 알 수 있는 것이 없기 때문이다` | 두 값이 거의 같아지는 것은 맞지만 이유가 다릅니다. 점수가 낮아도 정답이 라벨마다 고르게 나뉘어 있으면 두 지표는 나란히 움직입니다. |
| 2 | `주제분류만 평가셋의 주제별 건수가 크게 치우쳐 있어, 정확도만으로는 어느 주제에서 무너졌는지 드러나지 않기 때문이다` | **정답** |
| 3 | `주제분류는 라벨이 7개로 가장 많은데, 라벨이 2~3개뿐인 태스크에서는 macro-F1 을 계산할 수 없기 때문이다` | 라벨이 2개여도 macro-F1 은 계산됩니다 — `common.macro_f1` 은 라벨 목록을 그대로 돌며 F1 을 내고 평균할 뿐입니다. 라벨 개수는 조건이 아닙니다. |
| 4 | `주제분류만 T5 가 라벨 이름을 글자로 써내는 태스크라, 형식이 깨진 예측을 세려면 macro-F1 이 있어야 하기 때문이다` | 형식이 깨진 예측은 `broken_format` 이 따로 셉니다. 그리고 세 태스크 모두 T5·LLM 은 답을 글자로 써냅니다 — 주제분류만 그런 것이 아닙니다. |

**해설.**

**주제분류만 정답이 한쪽으로 몰려 있기 때문입니다.** 평가셋 300건 중 '사회'가 127건(42%)인데 '스포츠'는 15건뿐입니다.

정확도는 맞힌 건수를 300으로 나눈 값 하나입니다. 그래서 건수가 많은 주제의 성적이 그만큼 크게 반영됩니다. 극단적으로, 모든 제목을 '사회'라고만 찍어도 정확도는 42%가 나옵니다 — 일곱 주제 중 여섯을 하나도 못 맞혔는데도 그렇습니다.

macro-F1 은 다르게 셉니다. 주제마다 따로 정밀도와 재현율을 내어 F1 을 구한 뒤 **7개를 그냥 평균**합니다(`common.macro_f1`). 그래서 15건짜리 '스포츠'도 127건짜리 '사회'와 **똑같이 1/7 의 몫**을 차지합니다. 숫자로 보면 분명합니다. 나머지를 다 맞히고 '스포츠' 15건만 전부 틀렸다고 하면, 정확도는 100 에서 **95** 로 5점 떨어지는 데 그칩니다. 그런데 macro-F1 은 그 주제의 F1 이 0 이 되어 100 에서 **84.9** 로 내려갑니다 — 같은 실수가 세 배 크게 보입니다. 앞의 '전부 사회' 예측도 정확도는 42.3 이지만 macro-F1 은 **8.5** 입니다.

감성분류(230/270)와 자연어추론(99/104/97)은 정답이 라벨마다 고르게 나뉘어 있습니다. 그런 데이터에서는 두 지표가 거의 같이 움직여서 따로 볼 이유가 적습니다. **코드가 `if task == "tc"` 로 주제분류에만 macro-F1 을 붙인 것은 그래서입니다** — 지표를 많이 붙이는 것이 목적이 아니라, 정확도 하나가 가릴 수 있는 것이 이 데이터에만 있기 때문입니다. KLUE 벤치마크가 이 데이터셋(YNAT)의 지표로 macro-F1 을 두는 것도 같은 이유입니다.

여기서 남길 것은 지표 이름이 아닙니다. **점수 하나로 '잘한다'를 말할 수 있는지 먼저 확인해야 한다**는 것, 그리고 그 확인은 데이터의 생김새(정답이 고른가, 몰렸는가)를 보고 정해진다는 것입니다. 두 숫자의 차이가 벌어지면 §7 의 틀린 예를 다시 열어 어느 주제에서 무너졌는지 보세요.

### `q-tc-3` — 평가셋 300건으로 중간 점검을 하면

**문제.**

§5 에서 `L.train_bert(...)` 를 실행하면 학습이 시작되기 전에 이런 줄이 찍힙니다.

```
학습 720건 · 검증 80건 (학습 예제의 10%를 떼어 둠) — 13스텝마다 검증 점수를 함께 봅니다
```

학습셋 800건 중 80건을 떼어 **검증**에 쓰고, 학습에는 720건만 씁니다.
§2 에서 이미 따로 떼어 둔 **평가셋 300건**이 있는데, 왜 그것으로 중간 점검을 하지 않고 학습 예제를 줄여 가며 검증셋을 따로 만들까요?

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `검증도 학습의 일부라, 평가셋을 검증에 쓰면 그 300건이 모델의 가중치에 그대로 반영되기 때문이다` | 검증은 손실을 되돌려 가중치를 고치지 않습니다 — 점수를 재서 화면에 찍을 뿐입니다. 모델이 직접 외우는 것이 문제가 아니라, 그 숫자를 보고 **사람이** 결정을 내린다는 것이 문제입니다. |
| 2 | `평가셋 300건은 학습셋과 겹치지 않도록 만들어져 있어, 학습이 잘 되고 있는지 보는 용도로는 분포가 맞지 않기 때문이다` | 겹치지 않게 만든 것은 평가셋의 장점입니다(§2 의 `L.check_no_leak`). 분포가 안 맞아서 못 쓰는 것이 아닙니다. |
| 3 | `마지막에 점수를 낼 300건을 중간에 들여다보면, 그 점수를 더 이상 '처음 보는 문제'의 점수로 볼 수 없기 때문이다` | **정답** |
| 4 | `300건을 여러 번 예측하면 시간이 오래 걸려서, 같은 일을 80건으로 줄여 하는 것이다` | 300건 예측은 몇 초면 끝나고, 검증도 매 스텝이 아니라 몇 스텝마다 한 번만 합니다. 시간이 이유였다면 학습 예제를 720건으로 줄여 가면서까지 검증셋을 만들 이유가 없습니다. |

**해설.**

**마지막에 점수를 낼 300건을 중간에 들여다보면, 그 점수를 더 이상 '처음 보는 문제'의 점수로 볼 수 없기 때문입니다.**

`L.train_bert` 는 학습 예제의 10%를 떼어 검증셋으로 씁니다(`VAL_RATIO = 0.1`). 그래서 800건이 학습 720건 · 검증 80건으로 갈리고, 학습 도중 몇 스텝마다 검증 손실과 정확도가 함께 찍힙니다. 손실만 보면 "내려가고 있다"까지밖에 알 수 없지만, 검증 정확도를 함께 보면 "지금 얼마나 하는지"를 볼 수 있습니다.

검증 점수는 모델의 가중치를 바꾸지 않습니다. 그런데도 평가셋을 여기에 쓰면 안 되는 이유는, 그 숫자를 보고 **사람이** 결정을 내리기 때문입니다 — 에폭을 3에서 5로 올릴지, 학습률을 바꿀지, 어느 사전학습 모델을 쓸지. 결정에 쓴 데이터는 이미 '한 번 풀어 본 문제'입니다. 그 데이터로 최종 점수를 매기면 실제 성능보다 좋게 나옵니다.

그래서 몫을 셋으로 나눕니다.

- **학습 720건** — 가중치를 고치는 데 쓴다
- **검증 80건** — 학습이 잘 되고 있는지 보고, 에폭·학습률 같은 설정을 고르는 데 쓴다
- **평가 300건** — 마지막에 **한 번** 점수를 매기는 데 쓴다

§2 에서 `L.check_no_leak(train_rows, eval_rows)` 로 학습셋과 평가셋이 한 건도 겹치지 않는지 확인한 것도 같은 이야기입니다. 겹치면 점수가 부풀고, 그 점수로는 아무것도 판단할 수 없습니다. 검증셋이 너무 작으면 숫자가 크게 흔들려 볼 값이 못 됩니다. 그래서 `lab_common.py` 는 검증이 40건보다 적어지면 아예 나누지 않습니다(`VAL_MIN = 40`). 주제분류는 800건이라 80건이 떨어져 나눕니다.

### `m-sts-1` — 회귀 head의 출력은 몇 개인가

**문제.**

문장유사도는 두 문장이 얼마나 비슷한지 **0~5 사이의 값 하나**로 답합니다
(예: `3.3`). 앞의 주제분류처럼 후보 중 하나를 고르는 문제가 아닙니다.

이럴 때 head의 출력은 몇 개여야 할까요?

```python
return AutoModelForSequenceClassification.from_pretrained(
    MODEL, num_labels=____, problem_type="regression")
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `6` | 0,1,2,3,4,5 여섯 칸으로 나눈 셈입니다. 그러면 `3.3` 처럼 소수점이 있는 값을 낼 수 없고, 문제가 다시 '고르기'로 바뀝니다. |
| 2 | `1` | **정답** |
| 3 | `5` | 점수의 최댓값이 5인 것과 출력 개수는 다른 이야기입니다. 값의 범위가 아니라 '값 몇 개를 내는가'를 정하는 인자입니다. |
| 4 | `len(TC_LABELS)` | 주제분류의 라벨 개수(7)입니다. 이 노트북은 주제를 고르는 문제가 아닙니다. |

**해설.**

**`1`** — 출력 뉴런 하나입니다.

분류 head는 라벨마다 점수를 내고 그중 가장 큰 것을 고릅니다. 회귀 head는 **값 자체**를 내놓습니다.
그래서 출력이 하나이고, `problem_type="regression"` 을 주면 손실이 MSE로 바뀝니다
(예측과 정답의 차이를 제곱해 평균).

이 한 줄 차이로 같은 클래스가 전혀 다른 문제를 풉니다 — 이것이 head 를 바꾼다는 말의 뜻입니다.

```python
return AutoModelForSequenceClassification.from_pretrained(
    MODEL, num_labels=1, problem_type="regression")
```

### `m-sts-2` — 정답 점수를 어떤 형태로 넣을까

**문제.**

원본 데이터의 정답 점수는 이렇게 생겼습니다.

```python
r["raw"]["score"]     # 3.3
r["raw"]["binary"]    # 1     ← 3.0 이상인지 여부(이 실습에서는 쓰지 않는다)
```

회귀 head에 줄 라벨을 만들어야 합니다. 빈칸에 무엇을 넣을까요?

```python
enc["labels"] = [____ for r in rows]
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `int(r["raw"]["score"])` | 정수로 잘라 버립니다. `3.3` 이 `3` 이 되어 소수점 정보가 사라지고, MSE 손실도 형이 맞지 않아 문제가 생깁니다. |
| 2 | `r["raw"]["binary"]` | 0/1 로 뭉갠 값입니다. 그러면 '얼마나 비슷한가'가 아니라 '비슷한가 아닌가'를 배우게 되어 Pearson 상관이 크게 떨어집니다. |
| 3 | `float(r["raw"]["score"])` | **정답** |
| 4 | `str(r["raw"]["score"])` | 문자열이 됩니다. 손실은 수치 텐서에서 계산되므로 문자열 라벨로는 학습이 시작되지 않습니다. |

**해설.**

**`float(r["raw"]["score"])`**

정답이 `3.3` 처럼 연속된 값이므로 라벨도 **실수**여야 합니다. 정수로 자르면 소수점을 잃고,
MSE 손실은 예측과 정답을 같은 실수 텐서로 놓고 계산하므로 형도 맞아야 합니다.

`raw.binary` 는 3.0 이상인지만 표시한 값입니다. 그것으로 학습하면 '비슷한가 아닌가'만 배우게 되어,
이 실습의 지표인 Pearson 상관이 크게 떨어집니다.

```python
enc["labels"] = [float(r["raw"]["score"]) for r in rows]
```

**완성된 셀 전체입니다.** 앞 문항까지 다 풀었으니 여기서는 빈칸 없이 보여 줍니다 — 아래 [복사]를 눌러 미션 셀에 그대로 붙여 넣으셔도 됩니다.

```python
def build_model():
    # 출력이 하나뿐인 head + problem_type="regression" → 손실이 MSE(평균제곱오차)가 된다.
    return AutoModelForSequenceClassification.from_pretrained(
        MODEL, num_labels=1, problem_type="regression")


def encode_sts(tokenizer, rows, max_len=MAX_LEN):
    enc = tokenizer([r["input"]["sentence1"] for r in rows], [r["input"]["sentence2"] for r in rows],
                    truncation=True, max_length=max_len)
    enc["labels"] = [float(r["raw"]["score"]) for r in rows]
    return Dataset.from_dict(dict(enc))
```

### `m-sts-3` — 범위를 벗어난 예측을 어떻게 할까

**문제.**

회귀 head 는 출력이 하나뿐이라 그 값이 곧 예측 점수입니다.
그런데 **모델을 그 범위 안에 있으라고 묶어 둔 것이 없습니다** — 실제로 `-0.4` 나 `5.8` 같은 값이 나옵니다.
정답은 언제나 `0.0`~`5.0` 안에 있습니다.

채점 함수에 넣기 전에 값을 어떻게 다뤄야 할까요?

```python
values = np.asarray(logits).reshape(-1)      # 예제마다 실수 하나
return [f"{float(____):.1f}" for v in values]
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `np.clip(v, 0, 5)` | **정답** |
| 2 | `v` | 모델이 낸 값을 그대로 씁니다. `-0.4` 같은 값이 그대로 나가는데, 정답에는 그런 값이 없으므로 오차만 커집니다. |
| 3 | `round(v)` | 정수로 반올림합니다. 정답이 `3.3` 처럼 소수인데 `3` 으로만 답하게 되어 멀쩡히 맞힐 수 있던 것도 어긋납니다. |
| 4 | `v / 5` | 5로 나누면 0~1 범위가 됩니다. 정답의 눈금과 달라져 점수가 통째로 무너집니다. |

**해설.**

**`np.clip(v, 0, 5)`** 입니다.

회귀 head 는 마지막이 선형층이라 **출력에 범위 제한이 없습니다.** 0~5 짜리 정답으로 학습했으니 대개 그 근처를 내지만,
경계 쪽 예제에서는 `-0.4` 나 `5.8` 이 그대로 나옵니다. 정답에는 그런 값이 없으므로 **그대로 두면 오차만 커집니다.**
0 아래는 0으로, 5 위는 5로 밀어 넣으면 손해 볼 일이 없습니다.

**`:.1f` 도 함께 보세요.** 소수점 한 자리 문자열로 만드는 것은 **LLM 이 써내는 형식과 같게 맞추려는 것**입니다.
T5 와 LLM 은 `3.3` 이라고 글자로 답합니다. BERT 만 실수를 냅니다.
여기서 형식을 맞춰 두면 셋을 **하나의 채점 함수**에 그대로 넣을 수 있습니다.

**분류와 결정적으로 다른 곳이 여기입니다.** 주제분류는 후보 밖의 답이 원리상 나올 수 없지만,
회귀는 **범위 밖의 답이 나올 수 있습니다.** 출력을 그대로 믿지 않고 한 번 다듬어야 하는 이유입니다.

```python
return [f"{float(np.clip(v, 0, 5)):.1f}" for v in values]
```

**참고 자료.** [NumPy clip](https://numpy.org/doc/stable/reference/generated/numpy.clip.html) · [KLUE-STS 과제 정의](https://klue-benchmark.com)

### 퀴즈

### `q-sts` — 모든 예측을 3.0 으로 찍으면 점수가 어떻게 될까

**문제.**

문장유사도의 대표 지표는 **Pearson 상관**입니다(표에는 ×100).

어떤 모델이 학습에 완전히 실패해서 평가셋 300건 **전부를 `3.0` 이라고** 답했다고 해 봅시다.
정답들은 0~5 사이에 골고루 퍼져 있습니다. Pearson 상관은 얼마에 가까울까요?

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `60 쯤 — 평균값을 찍었으니 절반은 맞는 셈이다` | Pearson 은 '맞았다/틀렸다'를 세는 지표가 아닙니다. 정답과 **함께 변하는가**를 봅니다. |
| 2 | `100 — 예측이 하나도 흔들리지 않아 완벽하게 일관적이다` | 일관적인 것과 정답을 따라가는 것은 다릅니다. 상관은 두 값이 같이 움직이는 정도이지, 예측이 안정적인지가 아닙니다. |
| 3 | `0 에 가깝다 — 예측이 변하지 않으면 정답과 함께 오르내릴 수가 없다` | **정답** |
| 4 | `−100 — 정답과 반대 방향이다` | −100 은 정답이 오를 때 예측이 정확히 반대로 내려가는 경우입니다. 움직이지 않는 예측은 반대로도 가지 않습니다. |

**해설.**

**0 에 가깝습니다.**

Pearson 상관은 두 값이 **각자의 평균에서 얼마나 같은 방향으로 벗어나는가**를 봅니다.
예측이 전부 `3.0` 이면 예측 쪽 편차가 0 이라 곱해도 0 — 함께 움직인다고 할 것이 없습니다.
(엄밀히는 표준편차가 0 이라 식이 정의되지 않아, 구현에 따라 0 이나 `nan` 으로 나옵니다.
이 실습의 채점 함수는 0 으로 처리합니다.)

**정확도와의 차이가 여기서 드러납니다.** 정확도는 맞은 개수를 세지만, Pearson 은 순위 관계를 봅니다.
그래서 예측이 정답보다 전체적으로 조금 낮아도(예: 늘 0.5 씩 작게) 함께 오르내리기만 하면 높게 나오고,
반대로 평균 근처만 찍는 '안전한' 모델은 오차는 작아도 상관이 0 이 됩니다.

그래서 문장유사도에서는 **점수 하나만 보지 말고** 예측이 실제로 퍼져 있는지도 함께 봐야 합니다.

**참고 자료.** [Pearson 상관계수 — 정의와 수식](https://en.wikipedia.org/wiki/Pearson_correlation_coefficient) · [KLUE 논문 (STS 지표로 Pearson 을 쓰는 이유)](https://arxiv.org/abs/2105.09680)

### `q-sts-2` — 3.9 와 1.0 — 둘 다 틀렸지만 같은 틀림일까

**문제.**

정답이 `4.0` 인 문장 쌍이 있습니다. 모델 A는 `3.9`, 모델 B는 `1.0` 이라고 답했습니다.

이 실습처럼 **회귀(MSE)** 로 풀 때와, 0~5 를 여섯 개 라벨로 보고 **분류(교차엔트로피)** 로 풀 때,
두 답을 다루는 방식이 어떻게 다를까요?

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `회귀는 A와 B를 똑같이 '틀림'으로 보고, 분류가 A를 부분 정답으로 인정한다` | 방향이 뒤집혔습니다. 부분 점수를 주는 쪽이 **회귀**입니다. 라벨을 고르는 분류에는 '조금 틀림'이라는 것이 없습니다 — 고른 것이 정답 라벨이거나 아니거나입니다. |
| 2 | `회귀는 벗어난 정도를 제곱해 벌점을 매기므로 B가 훨씬 큰 벌을 받는다. 분류에게는 A도 B도 '정답 라벨이 아닌 것' 하나일 뿐이다` | **정답** |
| 3 | `둘 다 A와 B를 똑같이 다룬다 — 손실 함수는 맞았는지 틀렸는지만 본다` | 교차엔트로피는 그렇게 볼 수 있지만 MSE 는 다릅니다. 이름 그대로 **차이를 제곱해 평균**을 냅니다 — 멀리 벗어날수록 벌점이 가파르게 커집니다. |
| 4 | `회귀는 A와 B를 모두 통과시킨다 — MSE 는 0.5 이내의 차이를 오차로 세지 않는다` | MSE 에는 봐주는 구간이 없습니다. `0.1` 만 어긋나도 그만큼(제곱해서) 벌점이 생기고, 학습은 그 벌점을 줄이는 쪽으로 움직입니다. |

**해설.**

**회귀는 빗나간 정도를 재고, 분류는 재지 못합니다.**

MSE 는 차이를 제곱합니다.

```
A: (4.0 - 3.9)^2 = 0.01
B: (4.0 - 1.0)^2 = 9.0        ← 900 배
```

그래서 학습은 B 같은 답부터 급하게 고칩니다. 반면 여섯 개 라벨로 나눠 분류로 풀면,
모델이 고른 것이 `4` 가 아니라는 사실만 남습니다 — 교차엔트로피는 정답 라벨에 얼마의 확률을 줬는지를 보지,
**`3.9` 가 `1.0` 보다 정답에 가깝다는 것을 모릅니다.** 라벨끼리는 서로 이웃도 아니고 멀지도 않은,
그냥 다른 이름들이기 때문입니다.

**이것이 이 실습의 모양을 전부 결정합니다.** 정답 사이에 거리가 있는 문제이므로

- head 의 출력이 **하나**여야 하고 (`num_labels=1` — 고르는 것이 아니라 값을 낸다),
- 라벨을 **실수**로 넣어야 하며 (`float(...)` — 정수로 자르면 그 거리가 뭉개진다),
- 지표도 순서를 보는 **Pearson 상관**을 씁니다 (맞은 개수를 세는 정확도로는 '가까운 오답'을 인정할 수 없다).

세 가지가 따로 있는 규칙이 아니라 **한 가지 성질에서 나온 결과**입니다.
앞의 주제분류에서 이 셋이 모두 반대였던 이유도 같습니다 — 거기서는 라벨 사이에 거리가 없었습니다.

> 덧붙임. 회귀 head 는 값을 그대로 내놓기 때문에 `5.2` 나 `-0.1` 처럼 0~5 를 벗어난 값도 나올 수 있습니다.
> 그래서 채점 전에 0~5 로 잘라 씁니다 (`day1/lab_common.py` 의 `predict_sts`).

**참고 자료.** [PyTorch MSELoss — 차이를 제곱해 평균](https://pytorch.org/docs/stable/generated/torch.nn.MSELoss.html) · [PyTorch CrossEntropyLoss — 라벨을 고르는 손실](https://pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)

### `q-sts-3` — 시드만 바꿨는데 점수가 달라진다면

**문제.**

§5의 학습 셀에는 `L.set_seed(42)` 가 있고, §11의 3번은 이 값을 `7` 로 바꿔 다시 돌려 보라고 합니다.

데이터도 코드도 그대로인데 **시드만 바꿨더니** Pearson 이 눈에 띄게 달라졌다고 해 봅시다.
이것을 어떻게 읽어야 할까요?

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `코드가 잘못됐다 — 같은 코드는 시드와 상관없이 같은 점수를 내야 한다` | 시드는 새로 얹는 head의 무작위 초기값과 데이터를 섞는 순서를 정합니다. 시드가 다르면 다른 학습이므로 점수가 달라지는 것이 오히려 정상입니다. `L.set_seed(42)` 가 보장하는 것은 **같은 시드에서 같은 결과**입니다. |
| 2 | `시드 7 이 나쁜 값이다 — 42 처럼 널리 쓰는 값을 써야 제대로 학습된다` | 좋은 시드·나쁜 시드가 따로 있는 것은 아닙니다. 42 는 관례로 쓰는 숫자일 뿐이고, 어떤 시드에서 높게 나왔다면 그 시드가 좋아서가 아니라 그날 운이 그쪽이었던 것입니다. |
| 3 | `학습 예제가 600건뿐인 데다 회귀 head는 출력이 하나여서 무작위 초기값의 영향이 크게 남는다 — 점수 하나로 우열을 말하면 안 된다` | **정답** |
| 4 | `평가셋 300건이 적어서 생긴 일이다 — 학습은 똑같이 됐고, 평가셋을 늘리면 사라진다` | 평가셋은 두 번 모두 **같은 300건**입니다. 바뀐 것은 평가가 아니라 학습 쪽입니다. |

**해설.**

**학습 예제가 600건뿐이고 회귀 head는 출력이 하나여서, 무작위 초기값의 영향이 끝까지 남는 것입니다.**

시드는 새로 얹는 head의 초기값과 데이터를 섞는 순서를 정합니다. 시드를 바꾸면 다른 출발점에서
다른 순서로 배우게 되므로, 점수가 달라지는 것 자체는 고장이 아닙니다.
`L.set_seed(42)` 가 해 주는 일은 **같은 시드로 돌리면 같은 결과가 나오게** 하는 것 — 재현이지,
그 점수가 믿을 만하다는 보증이 아닙니다.

**이 실습만 `EPOCHS = 5` 인 이유가 여기에 있습니다**(다른 두 실습은 3).
§5에 적어 둔 대로, epochs 3에서 시드만 바꿔 재 보니 Pearson 이 **62에서 86까지** 흔들렸고,
epochs 를 5로 올리자 서로 다른 두 대의 GPU에서 세 시드 모두 **80~86** 으로 모였습니다.
그래서 이 노트북은 `task5-llm-ft/bert_baseline.py --mode budget` 과 이 값 하나만 다릅니다
(터미널에서 같은 결과를 보려면 `--epochs 5`).

남길 것은 이것입니다 — **데이터가 적으면 점수 하나를 믿으면 안 됩니다.**
시드를 바꿔 두세 번 돌려 보고 "몇 점"이 아니라 "몇 점에서 몇 점 사이"로 말하는 편이 정직합니다.
다른 모델과 비교할 때도 마찬가지입니다 — 한 번씩 돌려 나온 1~2점 차이는 우열의 근거가 되지 못합니다.

### `m-ner-1` — 특수 토큰 자리에는 어떤 라벨을 둘까

**문제.**

개체명인식은 **토큰마다** 태그를 답합니다. 그런데 토큰 중에는 `[CLS]`·`[SEP]` 처럼
**원문에 대응하는 글자가 없는** 특수 토큰이 섞여 있습니다(offset 이 `(0, 0)` 인 자리).

그 자리에는 정답이랄 것이 없으니, **손실 계산에서 아예 빼야** 합니다.
PyTorch 교차엔트로피가 "이 자리는 무시하라"고 알아보는 값이 정해져 있습니다.

```python
if e <= s:                     # [CLS]·[SEP] 같은 특수 토큰
    labels.append(____)
    prev_type = None
    continue
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `0` | 0 은 실제 태그 `O` 의 번호입니다. 무시되지 않고 "여기는 개체가 아니다"를 학습해 버립니다. |
| 2 | `-100` | **정답** |
| 3 | `L.BIO2ID["O"]` | `O` 태그를 넣는 것입니다. 손실에 그대로 들어가므로, 평가와 무관한 특수 토큰 자리까지 모델이 맞히려 애쓰게 됩니다. |
| 4 | `None` | `None` 은 텐서로 바꿀 수 없어 배치를 만드는 단계에서 오류가 납니다. |

**해설.**

**`-100`**

PyTorch 교차엔트로피는 `ignore_index` 로 지정한 라벨 값을 **손실 계산에서 완전히 뺍니다**.
그 기본값이 `-100` 이고, transformers 의 토큰 분류도 이 관례를 그대로 씁니다.

`O` 로 두면 어떻게 되는지 생각해 보세요. 문장마다 특수 토큰이 2개씩 들어가므로 짧은 문장에서는
비중이 작지 않고, 이미 데이터 대부분을 차지하는 `O` 가 더 늘어나 개체를 찾는 힘이 약해집니다.
패딩 자리도 같은 이유로 `-100` 이며, 그쪽은 `DataCollatorForTokenClassification` 이 자동으로 채워 줍니다.

```python
if e <= s:                     # [CLS]·[SEP] 같은 특수 토큰 — 원문 글자가 없다
    labels.append(-100)
    prev_type = None
    continue
```

**참고 자료.** [PyTorch CrossEntropyLoss — `ignore_index` 기본값](https://pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html) · [transformers — 토큰 분류(라벨 정렬 절)](https://huggingface.co/docs/transformers/tasks/token_classification)

### `m-ner-2` — 토큰의 태그를 어디서 가져올까

**문제.**

정답은 **글자마다** 붙어 있고(`cl` = `char_labels`), 모델이 보는 단위는 **서브워드 토큰**입니다.
그 둘을 이어 주는 것이 `offset_mapping` 입니다 — 토큰마다 `(시작 글자, 끝 글자)` 를 알려 줍니다.

```python
문장:  김  씨는  10  ##개월  후에  …
cl:    ['B-PS', 'O', 'O', 'O', 'B-DT', 'I-DT', …]   # 글자 단위
offset: (0,1)  (2,4)  (5,7)  (7,9)  (10,12)         # 토큰 단위
```

토큰 하나의 태그는 **그 토큰이 시작하는 글자의 태그**를 따릅니다. 빈칸을 채우세요.

```python
tag = ____ if s < len(cl) else "O"      # s = 이 토큰이 시작하는 글자 위치
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `cl[e]` | `e` 는 토큰이 **끝나는** 위치(그 다음 글자)입니다. 한 칸 밀린 태그를 가져오게 되고, 개체 경계가 어긋납니다. |
| 2 | `cl[s]` | **정답** |
| 3 | `cl[i]` | `i` 는 지금 몇 번째 **예제**인지를 세는 변수입니다. 글자 위치와 아무 관계가 없습니다. |
| 4 | `cl[s:e]` | 태그 하나가 아니라 **목록**이 됩니다. 뒤에서 `tag == "O"` 나 `tag.split("-")` 를 하므로 형이 맞지 않습니다. |

**해설.**

**`cl[s]`** — 토큰이 시작하는 글자의 태그입니다.

`offset_mapping` 의 `(s, e)` 에서 `s` 는 시작 글자, `e` 는 끝난 다음 글자입니다.
`cl[e]` 를 쓰면 한 칸 밀려 개체 경계가 어긋나고, `cl[s:e]` 는 태그 하나가 아니라 목록이 됩니다.

`if s < len(cl)` 이 붙어 있는 이유도 함께 보세요 — 토큰이 문장 길이를 넘어가는 자리를 `"O"` 로 막아,
목록 범위를 벗어나는 오류를 미리 피합니다.

```python
tag = cl[s] if s < len(cl) else "O"      # 토큰이 시작하는 글자의 태그를 따른다
```

**완성된 셀 전체입니다.** 앞 문항까지 다 풀었으니 여기서는 빈칸 없이 보여 줍니다 — 아래 [복사]를 눌러 미션 셀에 그대로 붙여 넣으셔도 됩니다.

```python
def build_model():
    # 토큰마다 태그 하나를 고르는 head. 태그는 BIO 13개(O + 6유형 × B/I).
    return AutoModelForTokenClassification.from_pretrained(
        MODEL, num_labels=len(L.BIO_LABELS),
        id2label=dict(enumerate(L.BIO_LABELS)), label2id=L.BIO2ID)


def encode_ner(tokenizer, rows, max_len=MAX_LEN):
    texts = [r["input"]["text"] for r in rows]
    enc = tokenizer(texts, truncation=True, max_length=max_len, return_offsets_mapping=True)
    all_labels = []
    for i, r in enumerate(rows):
        cl = r["raw"]["char_labels"]        # 글자 하나마다 "O" / "B-PS" / "I-PS" …
        labels = []
        prev_type = None
        for (s, e) in enc["offset_mapping"][i]:
            if e <= s:                     # [CLS]·[SEP] 같은 특수 토큰 — 원문 글자가 없다
                labels.append(-100)
                prev_type = None
                continue
            tag = cl[s] if s < len(cl) else "O"      # 토큰이 시작하는 글자의 태그를 따른다
            if tag == "O":
                labels.append(L.BIO2ID["O"])
                prev_type = None
            else:
                typ = tag.split("-")[1]
                bio = "B" if (tag.startswith("B") or typ != prev_type) else "I"
                labels.append(L.BIO2ID[f"{bio}-{typ}"])
                prev_type = typ
        all_labels.append(labels)
    enc["labels"] = all_labels
    enc.pop("offset_mapping")
    return Dataset.from_dict(dict(enc))
```

**참고 자료.** [transformers 토크나이저 — return_offsets_mapping](https://huggingface.co/docs/transformers/main_classes/tokenizer) · [transformers — 토큰 분류(서브워드와 라벨 정렬)](https://huggingface.co/docs/transformers/tasks/token_classification)

### `m-ner-3` — 언제 새 개체를 시작할까

**문제.**

모델은 **토큰마다** 태그를 하나씩 냅니다. 그것을 이어 붙여 개체 목록으로 만들어야 합니다.

태그는 `O`(개체 아님) · `B-PS`(사람 개체의 **시작**) · `I-PS`(사람 개체의 **이어짐**) 처럼 생겼습니다.

`김` `씨` `와` `이` `씨` 처럼 **사람 두 명이 나란히** 나오면 태그는 `B-PS I-PS O B-PS I-PS` 가 됩니다.
유형만 보고 이어 붙이면 두 사람이 한 덩어리가 되어 버립니다. 무엇을 보고 끊어야 할까요?

```python
bio, typ = tag.split("-")        # 예: "B-PS" → bio="B", typ="PS"
if bio == ____ or cur is None or cur["label"] != typ:
    ...                          # 새 개체를 연다
else:
    cur["end"] = e               # 앞 개체에 이어 붙인다
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `"B"` | **정답** |
| 2 | `"I"` | `I` 는 **이어짐**을 뜻합니다. 이어짐을 볼 때마다 새 개체를 열면 개체가 토큰 수만큼 쪼개집니다. |
| 3 | `"O"` | `O` 는 개체가 아니라는 뜻이라 이 자리에 오지 않습니다. 바로 위에서 이미 걸러냈습니다. |
| 4 | `typ` | `typ` 은 `PS`·`LC` 같은 **유형**입니다. `bio` 와 비교하면 언제나 다르므로 모든 토큰이 새 개체가 됩니다. |

**해설.**

**`"B"`** 입니다.

`B` 는 **개체가 여기서 시작한다**는 표시입니다. 그래서 `B` 를 만나면 앞에서 모으던 개체를 닫고 새로 엽니다.

**이것이 태그를 13개로 둔 이유입니다.** 유형만 있으면 7개(`O` + 6유형)로 충분한데 굳이
`O` + 6유형 × (`B-`, `I-`) = **13개**로 둔 것은, 유형만으로는 **같은 유형이 나란히 붙은 경우를 끊을 수 없기 때문**입니다.

`김 씨와 이 씨` 를 봅시다. 유형만 보면 `PS PS PS PS` 라서 네 토큰이 한 사람이 되어 버립니다.
`B-PS I-PS B-PS I-PS` 로 두면 두 번째 `B` 에서 끊어져 **두 사람**이 됩니다.

나머지 두 조건도 필요합니다.

- `cur is None` — 아직 아무것도 모으고 있지 않다면 당연히 새로 엽니다. `I-` 로 시작하는 예측이 나올 때를 위한 것입니다.
- `cur["label"] != typ` — 유형이 바뀌면 끊습니다. 모델이 `B-` 를 빠뜨려도 여기서 걸립니다.

**채점과 이어집니다.** 개체 단위 F1 은 개체 하나를 통째로 맞혀야 인정합니다.
두 사람을 한 덩어리로 내면 정답 두 개를 모두 놓치고 틀린 개체 하나를 더한 셈이 됩니다 — 부분 점수가 없습니다.

```python
if bio == "B" or cur is None or cur["label"] != typ:
```

### `q-ner` — B- 와 I- 를 나누는 이유

**문제.**

이 실습의 태그는 `O` 하나 + 6가지 유형 × (`B-`, `I-`) = 13개입니다.
유형만 쓰면 7개로 충분할 텐데, 왜 굳이 시작(`B-`)과 이어짐(`I-`)을 나눌까요?

```python
예문:  [김철수]PS [이영희]PS 님께      ← 사람 이름 두 개가 나란히
유형만:  PS PS PS  PS PS PS  O O
BIO  :  B-PS I-PS I-PS  B-PS I-PS I-PS  O O
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `태그가 많을수록 모델이 더 잘 학습하기 때문이다` | 태그를 늘리면 오히려 각 태그의 예가 줄어 학습이 어려워질 수 있습니다. 개수 자체가 목적이 아닙니다. |
| 2 | `붙어 있는 같은 유형의 개체 두 개를 하나로 합쳐 버리지 않기 위해서다` | **정답** |
| 3 | `B-` 는 학습에, `I-` 는 평가에 쓰는 태그라서다 | 둘 다 학습·평가에 함께 쓰입니다. 용도가 나뉘어 있는 것이 아닙니다. |
| 4 | 한국어에는 조사가 붙기 때문에 조사를 `I-` 로 표시하는 것이다 | 조사는 앞 개체에 붙는 별개 문제이고, `I-` 는 조사 표시가 아니라 '같은 개체가 이어진다'는 표시입니다. |

**해설.**

**붙어 있는 같은 유형의 개체를 나누기 위해서입니다.**

위 예문에서 유형만 쓰면 `PS` 가 여섯 칸 연달아 나옵니다. 그것만 보고는 **사람 이름이 하나인지 둘인지**
알 수 없습니다. `B-PS` 가 "여기서 새 개체가 시작한다"를 표시해 주어야 `김철수` 와 `이영희` 를
두 개로 되돌릴 수 있습니다.

이 실습의 채점이 **개체 단위 F1** 이라 차이가 그대로 점수에 나타납니다. 두 사람을 하나로 합치면
정답 2개를 모두 놓치고 틀린 개체 1개를 낸 셈이 되어, 정밀도와 재현율이 함께 깎입니다.

노트북의 확인 셀이 `I-` 앞에 반드시 같은 유형의 `B-` 나 `I-` 가 오는지 검사하는 것도 같은 이유입니다 —
그 규칙이 깨지면 예측을 개체 목록으로 되돌릴 수 없습니다.

**참고 자료.** [transformers — 토큰 분류(BIO 태깅)](https://huggingface.co/docs/transformers/tasks/token_classification) · [KLUE 논문 (NER 태그 체계와 개체 단위 F1)](https://arxiv.org/abs/2105.09680) · [KLUE 벤치마크](https://klue-benchmark.com)

### `q-ner-2` — 모든 토큰을 O 라고 답하면 점수가 어떻게 될까

**문제.**

학습 중간중간 화면에 두 가지 지표가 함께 찍힙니다 — **토큰 정확도**와 **개체 F1**입니다.
이 실습의 대표 지표는 그중 **개체 F1** 하나입니다(§6).

어떤 모델이 학습에 완전히 실패해서, 개체를 하나도 찾지 못하고 **모든 토큰에 `O` 라고** 답했다고 해 봅시다.
두 지표는 각각 어떻게 나올까요?

```python
문장:      김  씨는  10  ##개월  후에  재검을  …
정답:    B-PS   O   B-DT  I-DT   I-DT    O    …
이 모델:   O    O     O     O      O     O    …
```

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `토큰 정확도도 개체 F1 도 둘 다 0 에 가깝다` | 문장에서 개체에 해당하지 않는 자리가 개체인 자리보다 훨씬 많습니다. 그 많은 자리를 모두 맞힌 셈이 되므로, 토큰 정확도가 낮게 나오지는 않습니다. |
| 2 | `토큰 정확도는 꽤 높게 나오지만, 개체 F1 은 0 이다` | **정답** |
| 3 | `토큰 정확도는 0 이지만, 개체 F1 은 절반쯤 나온다` | `O` 도 13개 태그 중 하나이고, 정답이 `O` 인 자리에서는 맞은 것으로 셉니다. 두 지표를 거꾸로 보셨습니다. |
| 4 | `둘 다 50 쯤 나온다 — 절반은 맞고 절반은 틀린 셈이라서` | 두 지표는 세는 대상이 다릅니다. 하나는 토큰 자리를, 다른 하나는 찾아낸 개체를 셉니다. 나란히 절반이 되는 관계가 아닙니다. |

**해설.**

**토큰 정확도는 꽤 높게 나오고, 개체 F1 은 0 입니다.**

문장에서 개체에 해당하는 자리는 일부이고 나머지 대부분이 `O` 입니다. 그러니 전부 `O` 라고 답하면
그 많은 자리를 다 맞힌 셈이 되어 **토큰 정확도는 높게 나옵니다**. 하지만 개체는 하나도 내놓지 않았으므로
찾아낸 개체가 0개 — **개체 F1 은 0** 입니다.

이것이 이 태스크의 대표 지표를 정확도가 아니라 **개체 F1** 으로 둔 이유입니다. 우리가 알고 싶은 것은
"개체가 아닌 자리를 개체가 아니라고 잘 말하는가"가 아니라 "**개체를 얼마나 찾아내는가**"이기 때문입니다.

`lab_common.py` 에서 지표를 만드는 `metrics_for` 에도 같은 이유가 한 줄로 적혀 있습니다 —
개체 F1 을 셀 때 `O` 태그를 **빼고** 셉니다.

```python
ent = [t for t in BIO_LABELS if t != "O"]   # O 를 빼야 "개체를 얼마나 잡나"가 보인다
```

지표를 고르는 일은 취향이 아니라 **무엇을 잘하기를 바라는지 정하는 일**입니다. 여기서 정확도를 골랐다면
아무것도 찾지 않는 모델이 좋아 보였을 것이고, 학습도 그쪽으로 흘렀을 것입니다.

그래서 학습 화면에 토큰 정확도가 높게 찍혀도 그것만 보고 안심하면 안 됩니다. **개체 F1 쪽을 보세요.**

### `q-ner-3` — T5 는 형식이 깨질 수 있는데 BERT 는 왜 안 될까

**문제.**

§9 비교표에는 점수와 함께 **`형식깨짐`** 건수가 나옵니다. T5 는 답을 글자로 써내므로
대괄호를 덜 닫거나 JSON 앞뒤에 설명을 붙이는 일이 생길 수 있습니다.
그런데 BERT 쪽은 이 숫자가 **구조상 0** 입니다 — 운이 좋아서가 아닙니다.

BERT 가 실제로 내놓는 것과, 채점에 넣는 형식을 나란히 보세요.

```python
BERT 가 내놓는 것:  토큰마다 13개 태그 중 하나
                   [B-PS, O, B-DT, I-DT, I-DT, O, …]

채점에 넣는 형식:   [{"text": "김", "label": "PS"}, {"text": "10개월 후", "label": "DT"}]
```

BERT 에서는 왜 형식이 깨질 수 없을까요?

**보기.**

| | 보기 | 판정 |
|---|---|---|
| 1 | `BERT 도 JSON 을 써내지만, 학습 데이터가 전부 올바른 JSON 이라 형식을 정확히 익혔다` | BERT 는 이 실습에서 글자를 써내지 않습니다. 하는 일은 토큰마다 태그 하나를 고르는 것뿐입니다. |
| 2 | `BERT 는 정해진 13개 태그 중에서 고를 뿐이고, JSON 은 그 태그를 받아 코드가 조립하기 때문이다` | **정답** |
| 3 | `채점 함수가 BERT 의 출력만 예외로 봐주기 때문이다` | 채점 함수는 BERT·T5·2일차 LLM 이 모두 같은 것을 씁니다(`common.score_task`). 한쪽만 봐준다면 애초에 비교가 성립하지 않습니다. |
| 4 | `max_length=128` 로 길이를 제한해 두어 답이 중간에 잘리지 않기 때문이다 | 길이 제한은 긴 문장이 잘릴 수 있다는 것과 관련된 설정입니다. 길이를 넉넉히 줘도 써내는 모델은 여전히 형식을 깨뜨릴 수 있습니다. |

**해설.**

**BERT 는 13개 태그 중에서 고를 뿐이고, JSON 은 코드가 조립합니다.**

BERT 의 출력층은 토큰마다 13개 값 중 점수가 가장 높은 하나를 고릅니다. **그 밖의 값은 낼 수가 없습니다** —
형식이 깨질 자리 자체가 없습니다. 그 태그들을 개체 목록으로 되돌려 `[{"text": …, "label": …}]` 문자열로
만드는 것은 모델이 아니라 우리가 부른 코드입니다 — 미션 셀 ②에서 **여러분이 채운 `merge_bio`** 가 바로 그것입니다.

```python
preds = L.predict_bert(TASK, trainer, eval_ds, tokenizer, eval_rows, decode=merge_bio)   # §6
# 토큰 태그 → (B- 에서 끊어) 개체 목록 → JSON 문자열
```

T5 는 반대입니다. 지시문을 읽고 답을 **글자로 써냅니다.** 그래서 내용뿐 아니라 **형식까지 스스로 지켜야** 합니다.
채점 쪽은 예측에서 `[ … ]` 를 찾지 못하면 그 건을 `형식깨짐` 으로 셉니다.

이것이 노트북 첫머리 표의 "읽고 **고른다**" 대 "읽고 **써낸다**" 가 뜻하는 바입니다.

- 고르는 쪽(BERT): 형식을 어길 수 없다. 대신 태스크가 바뀌면 head 와 손실 함수를 바꿔야 한다.
- 써내는 쪽(T5·LLM): 무엇이든 쓸 수 있어 형식을 잃을 수 있다. 대신 지시문만 바꾸면 다른 태스크가 된다.

둘 중 무엇이 낫다기보다 **무엇을 얻고 무엇을 감수하는지가 다릅니다.**
2일차 LLM 도 써내는 쪽이라, 형식 문제는 그대로 따라옵니다.

### `m-sts` — 문장유사도 — 회귀 head 만들기와 실수 라벨 붙이기

```python
# ══════════════════════════════════════════════════════════════════════
#  미션 m-sts — 회귀 head 만들기와 실수 라벨 붙이기
# ══════════════════════════════════════════════════════════════════════
# 이 셀만 채우면 아래 셀들은 그대로 돌아갑니다. 다 채운 뒤 다음 '확인' 셀을 실행하세요.

def build_model():
    # num_labels=1 → 출력 뉴런이 하나.  problem_type="regression" → 손실이 MSE 가 된다.
    return AutoModelForSequenceClassification.from_pretrained(

def encode_sts(tokenizer, rows, max_len=MAX_LEN):

    return Dataset.from_dict(dict(enc))
```

### `m-ner` — 개체명인식 — 글자 단위 태그를 서브워드 토큰에 맞추기

```python
# ══════════════════════════════════════════════════════════════════════
#  미션 m-ner — 글자 단위 태그를 서브워드 토큰에 맞추기
# ══════════════════════════════════════════════════════════════════════
# 이 셀만 채우면 아래 셀들은 그대로 돌아갑니다. 다 채운 뒤 다음 '확인' 셀을 실행하세요.

def build_model():
    return AutoModelForTokenClassification.from_pretrained(
        MODEL, num_labels=len(L.BIO_LABELS),
        id2label=dict(enumerate(L.BIO_LABELS)), label2id=L.BIO2ID)


def encode_ner(tokenizer, rows, max_len=MAX_LEN):
    texts = [r["input"]["text"] for r in rows]
    enc = tokenizer(texts, truncation=True, max_length=max_len, return_offsets_mapping=True)
    all_labels = []
    for i, r in enumerate(rows):
        cl = r["raw"]["char_labels"]          # 글자 하나마다 "O" / "B-PS" / "I-PS" …
        labels = []
        prev_type = None
        for (s, e) in enc["offset_mapping"][i]:
            if e <= s:                                    # Step 1. 특수 토큰 — 손실에서 제외
                labels.append(-100)
                prev_type = None
                continue
            tag = cl[s] if s < len(cl) else "O"           # Step 2. 토큰 첫 글자의 태그를 따른다
            if tag == "O":
                labels.append(L.BIO2ID["O"])
                prev_type = None
            else:                                         # Step 3. B 인가 I 인가
                typ = tag.split("-")[1]
                bio = "B" if (tag.startswith("B") or typ != prev_type) else "I"
                labels.append(L.BIO2ID[f"{bio}-{typ}"])
                prev_type = typ
        all_labels.append(labels)
    enc["labels"] = all_labels
    enc.pop("offset_mapping")
    return Dataset.from_dict(dict(enc))
```

### 퀴즈

### `q-tc` — 주제분류 퀴즈

**질문.** 이 노트북에서 `num_labels`를 7로 준 이유는 무엇인가요? 만약 5로 주면 학습이 시작될까요, 아니면 어디에서 멈출까요?

**해답.** KLUE-YNAT의 주제 라벨이 일곱 가지(IT과학·경제·사회·생활문화·세계·스포츠·정치)이기 때문입니다. 분류 head는 라벨마다 점수 하나를 내는 선형층이라, 출력 개수가 곧 라벨 개수입니다. 5로 주면 모델은 만들어지지만 학습 중 라벨 5·6이 들어오는 순간 손실 계산에서 인덱스 범위를 벗어나 오류가 납니다(CUDA에서는 device-side assert). 그래서 코드에 7을 직접 적지 않고 `len(TC_LABELS)`로 쓰는 편이 안전합니다.

### `q-sts` — 문장유사도 퀴즈

**질문.** 회귀 head의 출력이 **하나**인 이유는 무엇인가요? 그리고 채점에 쓰는 Pearson 상관은 '정확도'와 무엇이 다른가요?

**해답.** 맞혀야 할 것이 '후보 중 하나'가 아니라 '0~5 사이의 값 하나'이기 때문입니다. 분류 head는 라벨마다 점수를 내고 그중 가장 큰 것을 고르지만, 회귀 head는 값 자체를 내놓습니다. 그래서 출력 뉴런이 하나이고, 손실도 교차엔트로피가 아니라 MSE(예측과 정답의 제곱 오차)입니다. Pearson 상관은 '예측이 정답과 같은 방향으로 함께 오르내리는가'를 -1~1로 잰 값입니다(표에는 ×100). 정확도와 달리 값이 조금 어긋나도 순위 관계가 맞으면 높게 나오고, 반대로 모든 예측을 3.0처럼 한 값으로 찍으면 변화가 없어 상관이 0에 가까워집니다.

### `q-ner` — 개체명인식 퀴즈

**질문.** 특수 토큰(`[CLS]`, `[SEP]`)의 라벨을 `-100`으로 둔 이유는 무엇인가요? `O`로 두면 무엇이 달라질까요?

**해답.** PyTorch의 교차엔트로피 손실은 라벨이 `-100`인 자리를 **아예 계산에서 뺍니다**(ignore_index 기본값). 특수 토큰은 원문에 대응하는 글자가 없으므로 정답이랄 것이 없고, 학습 신호로 삼을 이유도 없습니다. `O`로 두면 모델은 '특수 토큰 자리에는 O를 찍어라'라는, 평가와 무관한 일을 함께 배우게 됩니다. 문장마다 특수 토큰이 2개씩 들어가므로 짧은 문장에서는 그 비중이 작지 않고, 이미 데이터의 대부분을 차지하는 `O`가 더 늘어나 개체를 찾는 힘이 약해집니다. 패딩 자리도 같은 이유로 `-100`이며, `DataCollatorForTokenClassification`이 자동으로 채워 줍니다.
