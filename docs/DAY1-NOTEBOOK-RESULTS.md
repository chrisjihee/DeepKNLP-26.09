# 1일차 노트북 실측값 (2026-09-03)

출처: 강사판 노트북 세 개를 처음부터 끝까지 실행한 값이다.

`docs/LECTURE-FACTS.md` 의 BERT·T5 budget 표와 이 표는 **목적이 다르다.** LECTURE-FACTS 는 여섯 태스크를
같은 설정으로 쓸어 담은 스윕 결과이고, 여기는 1일차 실습 노트북이 실제로 출력한 값이다.
설정이 하나 다르면 값도 다르다. 서로 다를 때는 **강의 중 보여 주는 화면 기준으로 이 표를 쓴다.**

| 태스크 | 주 지표 | BERT (klue/roberta-base) | T5 (paust/pko-t5-base) |
|---|---|---:|---:|
| 주제분류 (KLUE-YNAT) | 정확도 | 80.00 | 82.67 |
| 문장유사도 (KLUE-STS) | 피어슨 상관 | 82.12 | 73.74 |
| 개체명인식 (KLUE-NER) | 개체 F1 | 79.72 | 71.21 |

**같은 코드를 다시 돌리면 숫자가 조금 움직인다.** 위 값은 커밋된 강사판 노트북의 출력이고,
그 전 실행에서는 BERT 80.00 / 84.25 / 79.72, T5 81.00 / 72.71 / 73.75 였다.
같은 기계·같은 시드인데도 **±2.5 안에서 흔들린다** — GPU 커널이 bf16 값을 더하는 순서가
실행마다 달라질 수 있기 때문이다(BERT 주제분류·개체명인식처럼 그 영향을 받지 않아 소수점까지
같게 나오는 경우도 있다). **학생 화면의 숫자가 이 표와 1~2점 다른 것은 정상이다.**
이것 자체가 이 실습에서 가르치는 것과 같은 이야기다 — 학습 예제가 수백~천 건일 때
점수 하나를 그대로 믿으면 안 된다.

- 학습 데이터: `data/llm-ft/train_main.jsonl` 의 해당 태스크(주제분류 800 · 문장유사도 600 · 개체명인식 1,000).
  평가: `data/llm-ft/eval_<태스크>.jsonl` 300건(공식 validation/test, 학습에 쓰지 않음).
- 설정: BERT 기본 epochs 3 · lr 5e-5 · batch 32 · max_len 128. **문장유사도만 epochs 5.**
  학습 예제가 600건뿐이라 epochs 3에서는 초기화 운에 따라 Pearson 이 62~86 사이로 흔들렸다.
  epochs 5로 올리니 시드 3개·기계 2대에서 모두 80 이상으로 안정됐다(추가 비용 약 2초).
  터미널에서 같은 값을 보려면 `python task5-llm-ft/t5_baseline.py`/`bert_baseline.py` 에 `--epochs 5` 를 붙인다.
- 실행 시간(강의장 PC): 노트북당 0.9 / 0.9 / 2.0분, 3개 합계 3.7분. GPU 최대 9.21GB.

## 읽는 법 — 세 방식의 성격 차이

주제분류처럼 답이 짧고 정해진 보기 안에 있는 문제는 BERT와 T5가 비슷하다(80.00 vs 81.00).
문장유사도처럼 **숫자를 정확히 맞혀야 하는** 문제는 BERT의 회귀 head 가 유리하다(84.25 vs 72.71) —
T5는 점수를 글자로 써내야 해서 소수점 자리를 맞추는 데 손해를 본다.
개체명인식처럼 **위치를 집어내야 하는** 문제도 BERT가 앞선다(79.72 vs 73.75).
이 차이가 2일차 LLM 실습으로 이어진다: 생성 모델은 라벨도 위치도 아닌 답(SQL·수식)까지 낼 수 있는 대신,
라벨·위치를 고르는 문제에서는 전용 head 를 붙인 인코더를 이기기 어렵다.
